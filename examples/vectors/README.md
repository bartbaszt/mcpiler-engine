# Vector search example

This example shows the external binary `vectors` section of Manifest 0.3. It explicitly
sets `authenticationRequired: false` because it is a synthetic local authoring example; do not
copy that open posture into a remotely reachable deployment without making the choice deliberately.

Files:

- `manifest.json` — a complete bundle root with two operations, a pinned lexical search
  section and an external vector section;
- `vectors.bin` — a deterministic MVMX version-1 matrix with two L2-normalized three-dimensional
  rows;
- `build_vectors.py` — the dependency-free generator that recreates `vectors.bin`.

The matrix header lists operation ids in exactly the same order as
`sections.search.inline.operations`:

```text
list-pets
get-pet
```

Rebuild it with:

```bash
python examples/vectors/build_vectors.py
```

The expected file is 150 bytes and has SHA-256:

```text
5019335ff2533f675e11eb2ded450dca7ff0bf61a4859e14ff707ca54a18ab1f
```

Those values are also declared in the root `vectors` entry. If you change the ids,
dimension, header or floats, either update the root metadata or omit `sha256`/`bytes` while
iterating and add them again for the finished bundle.

To inspect this example after generating or checking out `vectors.bin`:

```bash
dotnet mcpiler-engine.dll inspect \
  --mount /vectors=./examples/vectors \
  --file-store-root ./data
```

The three-dimensional vectors are intentionally synthetic. A production matrix must use
embeddings generated by the model named in the root `vectors.model` member, and the query
vector supplied to `catalogue.discover` must come from the same model and have the declared
dimension.

See [the Manifest vector-format reference](../../docs/manifest.md#vectors) for the byte layout
and refusal/degradation rules.
